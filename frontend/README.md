# HireGraph AI — Research Dashboard Frontend

> **"An Explainable AMRG-GraphSAGE Framework for Hiring Pattern Analysis under Evolving Job Requirements"**

---

## 1. Overview & Purpose

**HireGraph AI Frontend** is a research-oriented analytics and decision-support web application. It connects directly and exclusively to the **Spring Boot backend** (`http://localhost:8080/api/v1`) to present observational placement metrics, knowledge graph relationships, and deep graph neural network inference results generated by the **Adaptive Multi-Relational GraphSAGE (AMRG-GraphSAGE)** model.

### Key Conceptual Guarantees
- **Decision-Support vs. Guarantee:** All AI inference metrics represent **Model-estimated outcomes** based on historical recruitment patterns. They are explicitly not guaranteed hiring decisions.
- **Architectural Boundary:** The frontend never connects directly to PostgreSQL, Python, PyTorch Geometric, or FastAPI. All interactions flow strictly through Spring Boot.
- **Scientific Integrity:** The UI avoids synthetic feature attributions or fabricated GNN explanations. Observational candidate-job attribute comparisons are cleanly separated from model inference.

## 2. Technology Stack

- **Framework:** React 19 / React 18+ with TypeScript (Strict mode enabled)
- **Build Tool:** Vite 8
- **Routing:** React Router DOM (v7)
- **HTTP Client:** Axios with centralized interceptors, timeout handling, and friendly error transformations
- **Data Visualization:** Recharts (Bar charts, Line charts, Area charts)
- **Graph Visualization:** Cytoscape.js with CoSE layout, custom dark entity badges, zoom, pan, fit, and node inspection
- **Icons:** Lucide React
- **Styling:** Custom CSS design system with HSL dark mode, CSS custom properties, and full mobile responsiveness

## 4. Environment Variables

Create `.env` based on `.env.example`:

```bash
VITE_API_BASE_URL=http://localhost:8080/api/v1
```

If not provided, the client defaults to `http://localhost:8080/api/v1` with Vite reverse proxying `/api` in local development.

## 5. Installation & Execution

### Prerequisites
- Node.js 18+ (tested on Node v22.13.0)

```bash

# Install dependencies
npm install
```

## 8. Live Prediction Flow

1. User navigates to `/applications/:applicationId` (e.g. `A00001`).
2. User clicks **"Run Model Prediction"**.
3. Frontend dispatches `POST /api/v1/applications/{applicationId}/predict`.
4. Spring Boot verifies whether a cached prediction exists in PostgreSQL.
   - If present, Spring Boot returns the cached record immediately.
   - If absent, Spring Boot calls FastAPI `POST /predict/application/{id}`.
5. FastAPI executes forward inference using `AMRG_GraphSAGE_model.pt` on the frozen 5,977-node graph.
6. Spring Boot persists the prediction in PostgreSQL and returns the response.
7. Frontend displays:
   - **Model-Estimated Outcome:** `SELECTED` or `REJECTED`
   - **Estimated Probability:** e.g. `80.6%` (with animated probability bar)
   - **Side-by-Side Comparison:** Historical ground truth vs model estimate
   - **Prominent Disclaimer:** AI decision-support notice

## 9. Knowledge Graph Visualization

To prevent web browser crashes from rendering the entire network (5,977 nodes and 43,044 edges):
1. The page displays macro-level graph statistics (node counts by entity, relation types).
2. The user queries a focused entity by type (`Application`, `Student`, `Company`, `Job`, `Skill`) and ID.
3. The backend returns a localized 1-hop / 2-hop subgraph neighborhood (`GET /api/v1/graph/subgraph/{type}/{id}`).
4. Cytoscape.js renders the subgraph using the physics-based CoSE layout with distinct color badges, relation arrows, and zoom/pan/fit controls.

## 10. Explainability Status Limitation

The paper documents an experimental PyTorch Geometric edge-gradient compatibility limitation in the custom `RelationAwareWeightedSAGEConv` layer when computing GNNExplainer masks.
In accordance with research integrity standards:
- The UI **does not** fabricate heuristic feature attributions.
- A dedicated alert informs reviewers of the GNNExplainer status.
- Observable comparisons (CGPA vs cutoff, skill match ratios, experience alignment) are clearly presented as observable data attributes, not GNNExplainer outputs.
